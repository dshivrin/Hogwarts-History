# External Source Extraction Automation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the exhausted PDF extraction runtime with a lock-safe, one-source-per-unit workflow that processes all 63 acquired external snapshots through the existing canonical evidence indexes and generated outputs.

**Architecture:** A shared source-discovery helper exposes book and external evidence YAML to every downstream tool. A dedicated queue controller atomically claims and transitions manifest-derived units inside the existing `source-plan.yaml`, while serialized completion validates provenance, refreshes indexes and generated files, and advances compact processing state. The old runtime contract is preserved byte-for-byte before the new external-source contract becomes active.

**Tech Stack:** Python 3, PyYAML, `unittest`, `fcntl` filesystem locking on macOS, Markdown, YAML, `just`, and Git.

## Global Constraints

- Preserve every existing book source YAML and every completed book/companion queue record.
- Process exactly 63 external units in deterministic order A01-A37 followed by B01-B26.
- A worker writes only its assigned `sources/external/...yaml`; queue commands own state and generated-file updates.
- Never mark a unit `done` until its output validates and the complete index/generation workflow succeeds.
- Permit at most four simultaneous `in_progress` units.
- Use `capture_completeness`; remove the ambiguous manifest/snapshot key `completeness`.
- External entries keep `pdf_page`, `printed_page`, and `extracted_text_lines` present with null values.
- Routine agents use compact query commands and open only likely matching YAML files; they do not scan the whole evidence corpus.
- Do not edit generated outputs manually.
- The existing acquired Markdown body text is immutable during the metadata-key migration.
- Rollback baseline: Git commit `8ae640f` (`chore: checkpoint acquired source corpus`).

## File Map

- `scripts/source_files.py`: one canonical API for discovering book and external evidence YAML.
- `scripts/external_sources/queue.py`: manifest-to-queue generation, locking, claims, transitions, validation gates, and compact status output.

- `scripts/validate_source_yaml.py`: accepts both book/PDF and external/web provenance and rejects hashes or locators that do not match.
- `scripts/build_entry_index.py`, `scripts/build_duplicate_index.py`, `scripts/build_tag_index.py`: consume the shared discovery API and preserve external provenance.
- `scripts/generate_book_seed.py`, `scripts/generate_appendices.py`: render URL/source-ID provenance for web evidence without `PDF p. None`.
- `scripts/update_next_run.py`: renders current external queue state instead of assuming a chapter/PDF unit.
- `scripts/external_sources/build_external_corpus.py`: emits `capture_completeness`.
- `tests/external_sources/test_build_external_corpus.py`: asserts the renamed capture field.
- `resources/manifests/external-sources.yaml` and 63 `resources/external/**/*.md` files: metadata-key migration only; body hashes and body text remain unchanged.
